# DR-0013: Rubric v2 for the grown mutation-matrix row set

- Status: Accepted
- Date: 2026-10-15
- Decision owners: 2AM Logic
- Issue: #297 (PR #328)

## Decision

1. Adding the missing family faults (issue #297) changes the mutation-matrix
   row set: 44 to 50 required faults (identity 14, signal 17 to 20, timing 13
   to 16), 24 to 28 mandatory detectors, 13 to 19 sensitivity-`NO VERDICT`
   rows, and 20 to 21 CI subset rows. `spec/RUBRIC.md` says a row-set change
   creates a new rubric version, so this is **rubric v2**.
2. `spec/reference/rubric-v0.json` and `spec/reference/rubric-v1.json` are
   not edited, and neither is the artifact they pin:
   `sim/reference/mutation-matrix-v1.json` stays byte-identical to `main`.
   The regenerated matrix is published as
   `sim/reference/mutation-matrix-v2.json`
   (`kind: mutation-matrix-v2`, written by `tools/qualify_mutations_matrix.py`).
3. `spec/reference/rubric-v2.json` carries every v1 row, threshold and source
   over unchanged except the mutation-matrix source, which is repinned to the
   v2 matrix, and the recorded matrix counts above.
4. This is the operator disposition recorded on PR #328 (2026-10-15): cut
   v2, preserve v0/v1 bytes and their source artifacts, update the DR,
   validator and tests, and define any fresh-holdout policy before v2 is used
   for a new claim.

## Holdout

No holdout identity is read by this decision. Under DR-0011 a new rubric
version needs a fresh sealed holdout before it is used for a new claim.
`holdout-seal-v0.json` pins rubric v0 and is unchanged. **No fresh-holdout
policy is defined here**: rubric v2 must not be used for a release or holdout
claim until one is recorded.

## Scope

No target, arithmetic profile, noise policy, normalization, parameter order
or clip timing change. The mutation family publications
(`mutation-signal-v1.json`, `mutation-timing-v1.json`) are regenerated by the
PR and are not pinned by rubric v0 or v1. No fixed-point, RTL, synthesis,
hardware or sound-fidelity claim is made.

## Consequences

`tools/qualify_mutations_matrix.py --check` now validates the v2 matrix only.
The v1 matrix is a frozen historical artifact and is no longer regenerable
from the current tool.
